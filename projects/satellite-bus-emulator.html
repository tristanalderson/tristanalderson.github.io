Project

First CubeSat Platform

From-scratch flight computer for a 1U CubeSat — custom Yocto Linux running JPL's F Prime. Boot to telemetry from source.

Role

Platform architect, embedded Linux integration

Stack

Yocto, F Prime, Zynq UltraScale+, AXI4, Linux

Repo

satellite-bus-emulator

The Problem

CubeSats need flight software. Most teams either use commercial off-the-shelf systems or write everything from scratch. I wanted to build a flight computer using JPL's F Prime — the same framework NASA uses on Mars helicopters — on hardware I could actually afford and learn on.

What I built

A flight computer stack built entirely from source for the AMD Kria KV260. Custom embedded Linux (Yocto rel-v2024.2), JPL's F Prime flight software running on ARM Cortex-A53, telemetry and commanding over TCP to a ground station. Boot chain runs from factory QSPI to SD card image.

Cross-compilation uses the Yocto-generated SDK instead of a distro cross-compiler, so the toolchain and target rootfs share the same libc by construction. That one decision eliminates the "works on my toolchain, segfaults on the board" class of bug.

The 2024.2 setup uses the KV260's factory boot firmware before loading the SD image. I could have built my own from source, but there's nothing to gain and a bricked SOM to lose. I kept a recovery path. Deployment verified on hardware (July 2026)

What I'd do differently

I jumped straight into the 2024.2 hand-assembled Yocto config before understanding AMD's release structure. Now I'm migrating to EDF (Embedded Development Flow) — a reproducible, manifest-driven release that replaces bespoke layer assembly with vendor-maintained provenance. The migration plan is written and scaffolding is in place, but I haven't tested on hardware yet. I should have started with EDF. EDF migration branch

Highlights

  • Custom Yocto Linux platform built from source, F Prime v4.2.x running on ARM Cortex-A53
  • Boot to telemetry from source — factory QSPI → SD card → F Prime deployment → ground station
  • Yocto SDK approach eliminates toolchain/target libc mismatches
  • Factory QSPI preservation keeps a recovery path
  • Migration to AMD's EDF in progress for reproducible builds

Technical Stack

  • Hardware: AMD Kria KV260 (Zynq UltraScale+ K26 SOM)
  • Boot: Factory QSPI → SD (kernel + dtb + rootfs)
  • OS: Custom Yocto Linux (rel-v2024.2)
  • Machine: k26-smk-kv-sdt (SDT firmware flow)
  • Flight SW: F Prime v4.2.x (NASA JPL)
  • Cross-toolchain: Yocto-generated SDK
  • Ground Station: fprime-gds (TCP :50000)
