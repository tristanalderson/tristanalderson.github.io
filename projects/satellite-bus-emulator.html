Project

Satellite Bus Emulator

A from-scratch flight computer platform for the AMD Kria KV260 — custom Yocto Linux running JPL's F Prime, boot to telemetry from source.

Role

Platform architect, embedded Linux

Stack

Yocto, F Prime, Zynq UltraScale+, ARM Cortex-A53

Repo

satellite-bus-emulator

Why I Built This

I wanted to learn what actually sits between "bare silicon" and "spacecraft sends telemetry." Turns out the answer is mostly BitBake errors.

I have an AMD Kria KV260 dev board and wanted to follow a signal from a physical pin through programmable logic, software, telemetry, and a ground station. Eventually I'd like to design a custom PCB and maybe launch a CubeSat. For now this is where I'm learning.

What It Is

A flight computer stack built entirely from source for the KV260: custom embedded Linux (Yocto rel-v2024.2), JPL's F Prime flight software running on ARM Cortex-A53, telemetry and commanding over TCP to a ground station (fprime-gds), and boot chain from factory QSPI to SD card image.

The flight side connects as a TCP client. The ground station must be listening first.

Yocto SDK Approach

Cross-compilation uses the Yocto-generated SDK instead of a distro cross-compiler, so the toolchain and target rootfs share the same libc by construction. That one decision eliminates the "works on my toolchain, segfaults on the board" class of bug.

Factory QSPI Preservation

The 2024.2 setup uses the KV260's factory boot firmware before loading the SD image. I could have built my own from source, but there's nothing to gain and a bricked SOM to lose. I kept a recovery path.

Current State

The 2024.2 platform boots, runs the F Prime deployment, and exchanges telemetry/commands with the ground station over TCP. Deployment verified (July 2026)

I'm migrating to AMD's EDF (Embedded Development Flow) — a reproducible, manifest-driven release. Migration plan is written, scaffolding is in place, but I haven't tested on hardware yet. EDF migration branch

What I'm Learning

  • Follow a signal from physical pin through PL → software → telemetry → ground station
  • Design and verify RTL, understand timing and clock boundaries
  • Explore the division of work between Linux (A53), real-time software (R5), and FPGA logic

Technical Stack

  • Hardware: AMD Kria KV260 (Zynq UltraScale+ K26 SOM)
  • Boot: Factory QSPI → SD (kernel + dtb + rootfs)
  • OS: Custom Yocto Linux (rel-v2024.2)
  • Machine: k26-smk-kv-sdt (SDT firmware flow)
  • Flight SW: F Prime v4.2.x (NASA JPL)
  • Cross-toolchain: Yocto-generated SDK
  • Ground Station: fprime-gds (TCP :50000)
